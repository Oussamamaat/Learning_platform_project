## Project
A B2B multi-tenant, domain-agnostic, adaptive learning platform: an AI tutor that
tutors each tenant's users from that tenant's own course materials (RAG + a fine-tuned
LLM). Multilingual — **French primary, Darija secondary but mandatory, English in
scope**. MVP: personalized explanations, quiz generation from tenant content, and a
conversational assistant (text + audio).

**Tenant model.** Each tenant uploads its own documents and brings its own language
mix; onboarding means adding documents + a per-tenant LoRA adapter, not code changes.
Tenant #1 = Moroccan safety/security regulations, Darija (Arabic script) + French,
served by the `atlas-darija-tutor` model (LoRA fine-tune of Atlas-Chat-9B, GGUF via
Ollama). Platform direction: neutral multilingual base with per-tenant LoRA adapters
before tenant #2.

## Directory Layout
- `app/` — FastAPI backend: routers in `app/routers/` (chat, quiz, demo); services in
  `app/services/` — citations, generation gates, LLM adapter (`llm.py`, dual-model
  French/Darija routing), data-gen pipeline, plus `history.py` (server-side multi-turn
  memory), `routing.py` (auto domain/language routing), `retrieval.py`/`search.py`
  (pgvector + language-affinity retrieval), `domain_context.py` (disk-backend
  fallback), `learner_state.py` (seam, unwired). See `docs/architecture/` for how
  these fit together.
- `tests/` — pytest suite (368 tests as of 2026-08-13): `test_generation_gates.py`,
  `test_citations.py`, plus per-service tests (`test_history.py`, `test_routing.py`,
  `test_retrieval.py`, `test_domain_routing.py`, `test_quiz.py`, etc.)
- `data/`, `raw/` — training data and RAG corpus (Arabic/French regulatory docs)
- `config/` — Dockerfile, docker-compose.yml, requirements.txt
- `api/openapi.json` — generated by `app/services/export_openapi.py`; don't hand-edit
- `full_run_export/`, `incident_export/` — raw Kaggle run logs used to debug generation stalls
- `_archive/` — superseded docs/datasets/model exports kept for comparison; not active, don't build on it
- `kaggle_generation_v3.ipynb`, `kaggle_topup_v4.ipynb` — Kaggle generation kernel notebooks, sequential stages of one pipeline (base run + delta top-up), both still relevant
- `kaggle_finetune_v11.ipynb` — the fine-tune notebook that produced the adapter currently in production (`IBLOG_TUTOR`); copy this one when rebuilding a fine-tune kernel. Superseded prior versions (`kaggle_finetune_v3.ipynb`, `unsloth_finetune_atlas.ipynb`) have been moved to `_archive/model_exports_superseded/`
- `_archive/finetune_v1_2026-07-30/` — LoRA adapter, training report, and compile cache from a prior fine-tune run (2026-07-30); historical, not something to build on. As of 2026-08-02 this is adapter-only (244 MB) — the full merged fp16 weights (`atlas_gguf_export/`, 18 GB) and merged GGUF (`atlas_gguf_export_gguf/`, 5.4 GB) were deleted to reclaim disk space; both are reproducible from this adapter + base Atlas-Chat-9B, and the already-registered `atlas-darija-tutor:latest` Ollama model has its own independent blob copy so it was unaffected

## Data-generation invariants
- Output must be Arabic-script Darija, never Arabizi/Latin transliteration, and free of CJK/Hangul contamination — enforced at `app/services/generate_training_data.py:1677`.
- Citation extraction and script detection: `app/services/citations.py:126` and `:262`.
- Component gating (French-required vs. empty-context components): `app/services/generate_training_data.py:50`, `:123`, `:132`.
- Darija marker scoring used by generation gates: `app/services/generate_training_data.py:709`.
