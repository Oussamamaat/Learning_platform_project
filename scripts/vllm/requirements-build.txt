# Pinned deps for scripts/vllm/build_merged_awq.py (plan rev 2, Phase A7/B3).
#
# torch is deliberately NOT in this file, same convention as
# config/requirements.txt: install it FIRST from the cu128 index so the
# Blackwell (RTX 5090) build wins, then this file:
#
#   pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
#   pip install -r scripts/vllm/requirements-build.txt
#
# 2.11.0, not llmcompressor's own stated upper bound (2.13.0): checked
# 2026-09-10 against download.pytorch.org/whl/cu128's actual index --
# 2.11.0 is the newest version actually published there. Pinning 2.13.0
# (in range on paper) fails outright with "Could not find a version that
# satisfies the requirement" -- caught by this migration's own dry run,
# not assumed.
#
# The local dry run (plan Phase A7's gate -- a tiny random model, not a
# real 9B) STILL needs a real CUDA GPU, even though the model is tiny:
# llmcompressor's AWQModifier calls cache.pin_memory() unconditionally
# during its smoothing step, which raises `RuntimeError: Cannot access
# accelerator device when none is available` with no CUDA device present
# at all -- this is not merely slow on CPU, it doesn't run. Use the same
# cu128 install line above even for the dry run; there is no CPU path
# through this specific step of llm-compressor's AWQ implementation.
#
# All other versions pinned exactly (R6, plan rev 2) -- llmcompressor's AWQ
# call shape has moved before (rev 1 shipped against an API that no longer
# existed; see build_merged_awq.py's module docstring). Checked against
# PyPI 2026-09-10: llmcompressor 0.13.0 requires torch>=2.10,<=2.13 and
# transformers>=5.9,<=5.14.1 -- MUST run in its own venv, never
# .gguf_venv/.speech_venv/.tts_venv/.ocr_venv (those pin transformers 4.x
# for sentence-transformers/coqui-tts compatibility; installing this here
# would force-upgrade transformers across the whole app venv).
